# 长期技术路线图

## 目标

将当前 ROS2、MoveIt2 与 Gazebo 仿真原型逐步升级为可迁移到真实机械臂、具有量化工程证据的机器人操作系统。

`v1.0` 公开基线已经发布。当前按 M2 分步推进，同时保持复现性、失败样本、双语文档和冻结 `v1.0` 证据边界不被后续开发覆盖。

## 当前基线

- ROS2 Jazzy 节点化架构，覆盖感知、抓取生成、规划、执行、监测和验证。
- Franka Panda + MoveIt2 + OMPL + ros2_control + Gazebo Harmonic 双指接触抓取。
- ArUco 与无标记 RGB-D 目标定位，以及 tf2 坐标转换。
- 静态/动态障碍处理、剩余轨迹有效性检查、取消与实测状态重规划。
- fresh-world benchmark runner，保留原始失败、源码/配置指纹和 CSV/JSON/Markdown/SVG 报告。
- 中英文技术文档、运行截图、过程动画和 Gazebo 视频。
- 独立 C++17 包，包含可复用轨迹质量库、在线观察节点、gtest、ROS 图接入和 benchmark 导出。

当前仍为纯仿真系统。Gazebo 真值参与在线载荷监测和最终评分，主执行流水线以 Python 为主，尚未完成真机标定与硬件安全论证。

M1 已在冻结 `v1.0` 边界完成。2026-09-13 完成首个 M2 增量：两个包构建通过，当前开发树 colcon 汇总 `329` 项测试通过，已安装节点图产生 C++ 指标，并在一次 RGB-D fresh-world 物理 smoke 中把指标写入 CSV/Markdown。该单轮只证明集成链路，不形成新的可靠性结论。

## 里程碑

### M1：可信物理仿真闭环

状态：已在 `v1.0` 完成；不可变验收证据绑定源码版本 `2fa0440`。

- 冻结一个候选源码版本。
- 完成固定 10 次与固定种子随机 20 次 RGB-D 物理验收。
- 保留全部失败行并报告 Wilson 置信区间。
- 完成代表性静态障碍与安全停止注入证据。
- 严格区分规划成功和独立验证后的物理成功。

验收：固定场景 10/10，随机成功率不低于 85%，RGB-D 平均位置误差不高于 10 mm，平均放置误差不高于 50 mm，最终倾角不高于 15 度。

### M2：算法深度与 C++ 主线

状态：进行中。指标采集已迁移到 C++17 只读观察节点，任务管理与 MoveIt 指令权限仍保留在已验证的 Python 主流程。

- 分阶段将任务管理、MoveIt 调用与指标采集迁移到 C++17。
- 增加 MoveIt Task Constructor 对照流水线。
- 在环境支持时对比 OMPL、STOMP 与 Pilz 等采样、优化和工业轨迹方法。
- 使用可操作度、关节限位余量、障碍间距、路径长度和平滑度评分抓取候选。
- 增加 Jacobian 条件数、奇异位形和关节跳变诊断。

下一检查点：把可操作度与场景间距加入抓取候选评分，在固定候选集上完成消融，再评估第二类规划方法；规划器质量与物理可靠性分开统计。

验收：至少 90 组规划实验，比较成功率、耗时、长度、平滑度与最小障碍距离，并完成至少一项消融实验。

### M3：面向产品的软件架构

- 从实时 RGB-D 点云更新 PlanningScene 或 OctoMap。
- 使用 MoveIt Servo 完成有界短周期纠偏与障碍响应。
- 分离 `simulation` 与 `real_robot` 执行后端。
- 增加 Lifecycle、watchdog、超时、急停接入、速度限制和显式故障恢复。
- 规范 QoS、TF、时间同步、rosbag 回放、参数分层、clang-format、clang-tidy、gtest、pytest 与 CI。

验收：从空环境到演示不超过 8 条核心命令；单元、集成和系统检查自动运行；每个失败都有阶段、错误码和可回放日志。

### M4：真实机械臂迁移

- 通过实验室、创客空间、合作单位或租赁获得受监督的真机环境。
- 完成相机内参、畸变、eye-to-hand/eye-in-hand、TCP 与基座标定。
- 接入一款受支持的商用六轴或七轴机械臂。
- 测量关节跟踪误差、末端误差、系统延迟和重复定位精度。
- 落实真实工作区、速度、加速度、碰撞和急停限制。

验收：至少 20 次真实抓取实验，保留成功/失败视频、标定报告、误差统计和仿真到真机的差异分析。

### M5：运动控制与接触任务

- 实现阻抗、导纳或力位混合控制中的一项。
- 使用 Pinocchio、KDL 或 TRAC-IK 验证运动学/动力学。
- 增加插孔、按钮、抽屉或表面跟随等接触型任务。
- 量化接触力峰值、跟踪误差、稳态误差与稳定性。

### M6：高级方向

只选择一条主线深入：约束规划与 Task and Motion Planning、三维实例分割与 6D Pose、学习式抓取候选生成，或包含 PLC/Modbus、工位节拍和恢复逻辑的工业集成。

## 评测矩阵

| 类别 | 范围 | 最少样本 | 指标 |
| --- | --- | ---: | --- |
| 感知 | 固定/随机目标 | 30+ | 检测率、XYZ 误差、延迟 |
| 规划 | 3 规划器 x 30 场景 | 90+ | 成功率、耗时、长度、平滑度 |
| 静态障碍 | 三类障碍 | 30+ | 碰撞、最小间距、绕行率 |
| 动态障碍 | 多种速度 | 30+ | 停止、重规划、无碰撞率 |
| 物理抓取 | 固定/随机目标 | 30+ | 双指接触、抬升、掉落率 |
| 放置 | 多个目标区域 | 30+ | 误差、倾角、拖带率 |
| 故障恢复 | 注入故障 | 20+ | 恢复率、错误归因、安全停止 |

每份报告必须包含样本量、成功率、95% 置信区间、平均值、标准差、失败分类和可回放日志路径。

## 交付原则

- 持续维护 README、架构决策、CSV/Markdown/SVG 证据、演示视频和中英文技术文档。
- 稳定性、可复现性和可解释性优先于增加算法名词。
- 每次只处理一个主要失败模式，小样本验证后再扩大矩阵。
- 不把单次成功写成总体可靠性指标。
- 优先完成 C++、真机、标定、安全和故障恢复，再扩展 YOLO、VLA、强化学习或双臂。
- 自动化成功必须同时通过软件状态和物理结果验证。
